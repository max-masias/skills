1. QUÉ ES ESTO Y CÓMO ESTÁ ORGANIZADO
--------------------------------------------------------------------------

Una "skill" es un paquete de instrucciones (y a veces scripts) que le enseña
a Claude Code a hacer una tarea concreta siempre de la misma forma.

  Claude_skills\                (carpeta del repositorio; puede tener otro nombre)
  |-- .claude\skills\            Las 14 skills (una carpeta por skill)
  |-- Generador_facturas_AWS\    Proyecto de la skill factura-aws-acres
  |   |-- Comprobantes_AWS\        -> aquí van los PDF de AWS
  |   |-- Datos_Factura\           -> datos del emisor, de ACRES y numeración
  |   |-- Factura_generada\        -> aquí salen las facturas
  |-- Generador_informes_MD\     Proyecto de la skill informe-desde-md
  |   |-- Archivos_MD\             -> aquí van los .md de entrada
  |   |-- Informe_generado\        -> aquí salen los informes
  |-- entradas\                  Archivos de entrada del resto de skills
  |                                (Word, PDF de requerimientos, etc.)
  |-- salidas\                   Resultados, una subcarpeta por skill
  |-- CLAUDE.md                  Instrucciones para Claude (no editar salvo
  |                                que se cambien las skills)
  |-- INSTRUCCIONES_SKILLS.txt   Este archivo
  |-- requirements.txt           Librerías de Python necesarias

  Las skills parsear-documento y archivo-a-markdown son la excepción:
  todo lo suyo está dentro de su carpeta de skill:
  .claude\skills\parsear-documento\
  |-- SKILL.md, scripts\           la skill
  |-- Documentos_entrada\          -> aquí van los documentos a parsear
  |-- Documentos_parseados\        -> aquí salen los .md resultantes
  |-- configurar_parsear_documento.ps1   configurador (una sola vez)
  |-- plantilla_env.txt            modelo del .env
  |-- .env                         la clave (cada persona la suya; no se sube)
  |-- .llamaparse\                 registro de créditos gastados (no se sube)
  .claude\skills\archivo-a-markdown\
  |-- SKILL.md, scripts\           la skill
  |-- Archivos_entrada\            -> aquí van los archivos a convertir
  |-- Markdown_generado\           -> aquí salen los .md resultantes
  |-- configurar_archivo_a_markdown.ps1   configurador (una sola vez)

Regla general: lo que se le da a una skill va en su carpeta de entrada y
lo que produce aparece en su carpeta de salida. Nada se escribe dentro de
.claude\ salvo en las carpetas de parsear-documento y
archivo-a-markdown.


--------------------------------------------------------------------------
2. PREPARAR EL EQUIPO (UNA SOLA VEZ)
--------------------------------------------------------------------------

a) Claude Code: en la terminal, en VS Code / Antigravity (extensión de
   Claude) o en la app de escritorio.

b) Python 3.10 o superior (python.org o Anaconda). Comprobar en una
   terminal:   python --version

c) Librerías: abrir una terminal en la carpeta del repositorio y
   ejecutar:
       python -m pip install -r requirements.txt
   (si "python" no funciona, probar con "py").

d) Solo para /parsear-documento: seguir la guía paso a paso de la sección
   4.13 (un comando que instala todo y pide pegar la clave de LlamaCloud).
   Para /archivo-a-markdown: un comando (sección 4.14); no necesita
   cuenta ni clave.

e) Opcional: pandoc (https://pandoc.org) mejora la conversión de Word a
   Markdown. Sin pandoc la skill docx-a-markdown funciona igual.

f) Abrir SIEMPRE la carpeta del repositorio completa en el editor
   (no una subcarpeta). Así Claude Code carga las skills y el CLAUDE.md.


--------------------------------------------------------------------------
3. CÓMO LLAMAR A UNA SKILL
--------------------------------------------------------------------------

Hay dos formas, en el chat de Claude Code:

  - Con el comando:  escribir "/" y el nombre, por ejemplo
        /factura-aws-acres
    Al escribir "/" aparece la lista; se puede filtrar escribiendo parte
    del nombre (por ejemplo "/fact").

  - Pidiéndolo con palabras: "genera la factura de AWS para ACRES",
    "hazme un análisis CAGE de ...". Claude elige la skill adecuada.

Para señalar un archivo concreto se escribe "@" y su ruta, por ejemplo
@entradas/requerimientos.pdf. En las skills de factura e informe no hace
falta: ya saben en qué carpeta buscar.

Si se acaban de agregar o cambiar skills, cerrar el chat y abrir uno nuevo
para que se vuelvan a cargar.

..........................................................................
4.1  /factura-aws-acres  -  Factura a ACRES por servicios de AWS
..........................................................................
Qué hace : Lee los estados de cuenta de AWS (un PDF por cuenta: PROD,
           UAT...), verifica que todos los montos cuadren y genera la
           factura en PDF para ACRES SAFI (Perú): IGV 18 %, detracción,
           importe en letras y anexos con el detalle de consumo.
Antes    : 1) Completar una vez Generador_facturas_AWS\Datos_Factura\
              - cliente.json      (RUC, dirección y encargado de ACRES)
              - emisor.json       (datos de la empresa que factura, bancos)
              - facturacion.json  (serie, número de la próxima factura...)
              Mientras quede algún [COMPLETAR], sale un BORRADOR que no
              gasta número de factura.
           2) Copiar los PDF de AWS del mes en
              Generador_facturas_AWS\Comprobantes_AWS\
Pedir    : /factura-aws-acres   o   "genera la factura de AWS de este mes"
Resultado: Generador_facturas_AWS\Factura_generada\<AAAA-MM>\
           Factura_<número>_ACRES_AWS_<AAAA-MM>.pdf
           y el registro de facturas emitidas en registro_facturas.csv
Notas    : No factura dos veces el mismo mes. Para rehacer una factura:
           "regenera la factura de 2023-07". El PDF es el sustento; el
           comprobante electrónico se emite en el sistema de facturación
           de la empresa con el mismo número e importes.

4.13 /parsear-documento  -  Documentos difíciles a Markdown con LlamaParse
..........................................................................
Qué hace : Sube el documento a LlamaParse (servicio en la nube de
           LlamaIndex) y devuelve su contenido en Markdown o texto. Sirve
           para PDF escaneados, fotos de documentos, tablas complejas,
           PowerPoint y Excel. Antes de subir nada calcula cuántos
           créditos costará y se detiene si se pasaría del límite del mes.
Antes    : Configuración, una sola vez por equipo (unos 10 minutos).
           Ver la guía paso a paso justo debajo.
Pedir    : /parsear-documento   (procesa los documentos de
           Documentos_entrada que todavía no tienen resultado)
           /parsear-documento @ruta/archivo.pdf   -> un archivo concreto
           "¿cuánto costaría?"            -> solo estima, no gasta créditos
           "¿cuántos créditos me quedan?" -> muestra el consumo del mes
Resultado: .claude\skills\parsear-documento\Documentos_parseados\<archivo>.md
           (nunca sobrescribe: si se repite, crea <archivo>_v2.md)
Créditos : El plan gratuito trae 10.000 créditos por mes (no se acumulan).
           Costo por página: fast 1 · cost_effective 3 · agentic 10 ·
           agentic_plus 25. Con 10.000 créditos alcanzan, por ejemplo,
           ~3.300 páginas de documentos digitales o 1.000 escaneadas.
           Re-parsear el mismo archivo dentro de 48 h no cuesta.
           La skill registra lo gastado en .llamaparse\consumo.csv, dentro
           de su carpeta (solo lo hecho con esta skill en este equipo; el
           saldo oficial está en cloud.llamaindex.ai).
Notas    : El documento se sube a los servidores de LlamaIndex (quedan en
           caché 48 h, no se usan para entrenar modelos y la skill borra el
           archivo al terminar). Confirmar que está permitido antes de
           subir documentos de clientes. Para un Word sencillo,
           /docx-a-markdown es gratis y no sube nada.

  CONFIGURACIÓN DE /parsear-documento - PASO A PASO (una sola vez)
  -----------------------------------------------------------------

  Paso 1. Traer la última versión del repositorio
          Si es la primera vez:  git clone https://github.com/chriscev/Claude_skills.git
          Si ya lo tenías:       git pull      (dentro de la carpeta del repositorio)

  Paso 2. Crear la cuenta de LlamaCloud (plan gratuito)
          - Entrar a https://cloud.llamaindex.ai y registrarse (con Google,
            GitHub o correo). Región: dejar la de Norteamérica (NA), salvo
            que se necesite Europa (https://cloud.eu.llamaindex.ai). La
            región no se puede cambiar después.
          - El plan gratuito ("Pay as you go") trae 10.000 créditos al mes.

  Paso 3. Crear la clave (API key)
          - En el menú izquierdo: API Key -> Generate New Key -> escribir un
            nombre (p. ej. "skills-claude") -> Create new key.
          - Copiar la clave (empieza con "llx-"). Se muestra UNA sola vez;
            si se pierde, se crea otra.
          - La clave es personal: no se comparte, no se pega en chats y no
            se muestra en capturas de pantalla.

  Paso 4. Ejecutar el configurador
          - Abrir PowerShell (menú Inicio -> escribir "PowerShell" -> Enter).
          - Ir a la carpeta del repositorio (cambiar la ruta por la propia):
                cd "C:\ruta\a\Claude_skills"
          - Ejecutar:
                powershell -ExecutionPolicy Bypass -File .\.claude\skills\parsear-documento\configurar_parsear_documento.ps1
            (todo en una sola línea)
          El configurador hace solo:
            a) Instala Python 3.12 si no está (con winget o desde python.org,
               sin pedir permisos de administrador). Tarda unos minutos.
            b) Instala las librerías de requirements.txt.
            c) Crea el archivo .claude\skills\parsear-documento\.env a partir
               de la plantilla_env.txt de esa misma carpeta.
            d) Abre ese .env en el Bloc de notas.

  Paso 5. Pegar la clave
          - En el Bloc de notas, en la línea
                LLAMA_CLOUD_API_KEY=llx-pega-aqui-tu-clave
            reemplazar  llx-pega-aqui-tu-clave  por la clave propia. Debe
            quedar  LLAMA_CLOUD_API_KEY=llx-...  sin comillas ni espacios.
          - Guardar (Ctrl+S) y cerrar esa pestaña del Bloc de notas.
          - Si el configurador se queda esperando (pasa cuando el Bloc de
            notas tiene otras pestañas abiertas), cerrar la PowerShell, abrir
            otra y repetir el Paso 4: ya no pedirá la clave.

  Paso 6. Comprobar el resultado
          Al final, el configurador muestra en verde:
              Python y librerías: OK
              Clave encontrada: llx-...XXXX (NN caracteres)
              .env excluido de GitHub: OK
              Listo. Copia un documento en .claude\skills\parsear-documento\Documentos_entrada\ ...
          Si algo sale en rojo o amarillo, corregirlo y repetir el Paso 4.
          Se puede ejecutar todas las veces que haga falta: no borra nada
          ni cambia una clave ya guardada.

  Paso 7. Primera prueba
          - Copiar un documento corto (1-2 páginas) en
            .claude\skills\parsear-documento\Documentos_entrada\
          - Abrir la carpeta del repositorio en Claude Code y empezar un chat
            NUEVO (para que cargue la skill).
          - Escribir:  ¿cuánto costaría parsear los documentos?   (no gasta)
          - Escribir:  /parsear-documento
          - El resultado aparece en
            .claude\skills\parsear-documento\Documentos_parseados\
          - El saldo oficial se ve en cloud.llamaindex.ai.

  Qué NO se sube a GitHub (lo excluye .gitignore):
          - .claude\skills\parsear-documento\.env (la clave)
          - .claude\skills\parsear-documento\.llamaparse\ (registro local de consumo)
          - el contenido de Documentos_entrada y Documentos_parseados

4.14 /archivo-a-markdown  -  Cualquier archivo a Markdown en el propio equipo
..........................................................................
Qué hace : Lo mismo que /parsear-documento (un .md por archivo, con
           títulos, párrafos, listas, tablas, el texto de las imágenes y un
           separador por página), pero TODO en este equipo y solo con
           librerías de Python: sin internet, sin cuenta, sin clave y sin
           créditos. El documento nunca sale del computador, así que es la
           opción para documentos de clientes o confidenciales.
           Lee PDF digitales y escaneados (con OCR en español), Word,
           PowerPoint, Excel, CSV e imágenes.
Antes    : Una sola vez por equipo. En PowerShell, desde la carpeta del
           repositorio:
             powershell -ExecutionPolicy Bypass -File .\.claude\skills\archivo-a-markdown\configurar_archivo_a_markdown.ps1
           (todo en una sola línea). Instala Python 3.12 si falta (sin
           permisos de administrador), las librerías de requirements.txt
           (unos 150 MB la primera vez) y prueba el OCR. Al final debe
           mostrar en verde:
             Python y librerías: OK
             OCR (escaneados e imágenes): OK
             Archivos de entrada y resultados excluidos de GitHub: OK
             Listo. ...
           Después: cerrar y volver a abrir VS Code / Antigravity.
Pedir    : /archivo-a-markdown   (convierte los archivos de
           Archivos_entrada que todavía no tienen resultado)
           /archivo-a-markdown @ruta/archivo.pdf  -> un archivo concreto
           "¿cuánto tardaría?"   -> estima el tiempo sin convertir nada
           "solo las páginas 1 a 10" -> convierte solo esa parte
Modos    : Igual que los niveles de LlamaParse, se puede pedir uno:
             rápido   (= fast)           texto y tablas; lo más veloz
             estándar (= cost_effective) por defecto: + texto de imágenes,
                                         tablas combinadas y unidas entre
                                         páginas, índice como tabla, y
                                         Claude pasa los diagramas a
                                         Mermaid (como LlamaParse)
             preciso  (= agentic)        + tablas sin bordes, OCR a mayor
                                         resolución, fotos corregidas
             agente   (= agentic_plus)   preciso + Claude revisa también
                                         tablas, OCR dudoso e imágenes
                                         mirando la imagen
           Ejemplos: "/archivo-a-markdown en modo preciso",
                     "conviértelo con la máxima calidad, como LlamaParse"
           Para revisar diagramas y lo dudoso, Claude ve la imagen de esas
           partes; la conversión en sí sigue siendo local. Para que nada
           pase por Claude: "sin revisión" (los diagramas salen como texto).
Opciones : Se piden con palabras, por ejemplo:
           "las tablas en HTML" · "también un Excel con las tablas" ·
           "guarda las imágenes" · "con capturas de cada página" ·
           "respetando la disposición (formulario)" · "incluye las
           diapositivas ocultas" · "sin leer las imágenes" ·
           "ignora el 8 % de arriba de cada página"
           Siempre activo: enlaces, quitar marcas de agua y texto oculto,
           quitar encabezados y pies repetidos, datos de gráficos de
           PowerPoint como tabla, cambios controlados de Word aplicados.
Entrada  : .claude\skills\archivo-a-markdown\Archivos_entrada\
Resultado: .claude\skills\archivo-a-markdown\Markdown_generado\<archivo>.md
           (nunca sobrescribe: si se repite, crea <archivo>_v2.md)
Tiempo   : PDF digital: menos de 1 s por página. Páginas escaneadas e
           imágenes (OCR): unos 4 a 12 s por página según el modo y el
           equipo.
           Ejemplo real: documento técnico de ACRES (18 páginas, 3 con
           diagramas) en unos 50 s; plan de negocio en Word de 103 páginas
           con 20 imágenes en unos 2 minutos.
Calidad  : En el documento técnico de ACRES recuperó el 97,7 % del texto
           que obtuvo LlamaParse, con la misma estructura de títulos y
           listas. Diferencias: los diagramas salen como el texto que
           contienen (LlamaParse los redibuja); las tablas de PDF sin
           líneas y las de escaneos salen como texto; la letra manuscrita
           se lee mal. En esos casos, si el documento puede subirse a la
           nube, usar /parsear-documento (sección 4.13).
Notas    : No lee los formatos antiguos .doc, .ppt ni .xls: guardarlos
           como .docx, .pptx o .xlsx desde Office. Tampoco PDF con
           contraseña de apertura (guardarlos sin contraseña). Las fotos de
           celular se enderezan solas. El contenido de Archivos_entrada y
           Markdown_generado no se sube a GitHub.
           Diferencia con /docx-a-markdown: aquella es solo para Word;
           esta acepta cualquier formato.

5. PROBLEMAS FRECUENTES
--------------------------------------------------------------------------

- No aparece la skill al escribir "/":
  abrir la carpeta del repositorio completa (no una subcarpeta) y
  empezar un chat nuevo.

- "No module named ..." o falta una librería:
  python -m pip install -r requirements.txt

- "python" no se reconoce:
  usar "py" en su lugar, o reinstalar Python marcando "Add to PATH".

- La factura sale como BORRADOR:
  quedan campos [COMPLETAR] en Generador_facturas_AWS\Datos_Factura\.

- /parsear-documento dice "Falta la clave de LlamaCloud":
  falta el archivo .claude\skills\parsear-documento\.env o la línea
  LLAMA_CLOUD_API_KEY=llx-...; volver a ejecutar
  el configurador (ver 4.13, Paso 4).

- El configurador dice "Falta Python" o "No se pudo instalar Python":
  instalar Python desde https://www.python.org/downloads/ marcando
  "Add python.exe to PATH", abrir una PowerShell NUEVA y repetir el Paso 4.

- PowerShell dice "la ejecución de scripts está deshabilitada":
  usar el comando completo con  -ExecutionPolicy Bypass  (Paso 4); no hace
  falta cambiar ninguna configuración de Windows.

- /parsear-documento da error 401 (clave no válida):
  la clave está mal copiada o fue eliminada; crear otra (Paso 3) y
  reemplazarla en el .env (Paso 5). Si la cuenta es de Europa, quitar el #
  de la línea LLAMA_CLOUD_BASE_URL del .env.

- /parsear-documento se detiene por presupuesto:
  se acabaron los créditos del mes; usar menos páginas (--paginas), un
  tier más barato o esperar al día 1 del mes siguiente.

- /archivo-a-markdown dice "Faltan librerías de Python":
  ejecutar el configurador de la sección 4.14 (o, desde la carpeta del
  repositorio: python -m pip install -r requirements.txt).

- /archivo-a-markdown dice "Formato no soportado" con .doc/.ppt/.xls:
  abrir el archivo en Office y guardarlo como .docx, .pptx o .xlsx.

- /archivo-a-markdown tarda mucho:
  son páginas escaneadas o con muchas imágenes (el OCR es lo lento). Pedir
  solo algunas páginas, o "sin leer las imágenes" si no hacen falta.

- Claude pide permiso para ejecutar comandos:
  es normal la primera vez; se puede elegir "permitir siempre" para los
  scripts de las skills.
