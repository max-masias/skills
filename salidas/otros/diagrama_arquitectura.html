Patrones de Migración Clave

Los 4 cambios de código más críticos con ejemplos concretos

🔴
Patrón 1 — EJB DAO → Spring Data JPA Repository
❌ Antes (Java EE)
@Stateless
@TransactionAttribute(REQUIRED)
public class HolderAccountDAO
    extends CrudDaoServiceBean {

  @Inject
  private UserInfo userInfo;

  public List<HolderAccount> allByParticipant(
      Participant p,
      HolderAccountStatusType... s) {

    StringBuilder q = new StringBuilder();
    q.append("SELECT ha FROM HolderAccount ha ");
    q.append("WHERE ha.participant=:P");
    // params map, listByQueryString()
    return super.listByQueryString(q, params);
  }
}
✅ Después (Spring Boot)
@Repository
public interface HolderAccountRepository
    extends JpaRepository<HolderAccount, Long> {

  @Query("""
    SELECT ha FROM HolderAccount ha
    JOIN ha.participant p
    WHERE p.idParticipantPk = :id
    AND (:#{#states == null} = true
         OR ha.stateAccount IN :states)
    """)
  List<HolderAccount> findByParticipant(
    @Param("id") Long participantId,
    @Param("states") List<Integer> states
  );
}

@RestController
@RequestMapping("/api/v1/holders")
@RequiredArgsConstructor
public class HolderController {

  private final HolderService holderService;

  @GetMapping
  public Page<HolderDTO> search(
      @ModelAttribute HolderSearchDTO filter,
      Pageable pageable) {
    return holderService.search(filter, pageable);
  }

  @PostMapping
  @ResponseStatus(CREATED)
  public HolderDTO create(
      @Valid @RequestBody HolderRequestDTO dto) {
    return holderService.create(dto);
  }
}

Patrón 3 — Batch Propio → Spring Batch
❌ Antes — BatchServiceBean (EJB)
@Stateless
public class HolderCreationProcessBatch {

  @EJB private BatchServiceBean batchSvc;
  @EJB private HolderServiceBean holderSvc;

  public void execute(
      List<MassiveHolderTO> holders) {

    batchSvc.executeParallel(
      holders,
      holder -> holderSvc.create(holder)
    );
  }
}
✅ Después — Spring Batch Job
@Configuration
@RequiredArgsConstructor
public class HolderCreationJobConfig {

  @Bean
  public Step holderCreationStep() {
    return new StepBuilder("holderStep", repo)
      .<HolderDTO, Holder>chunk(50, tx)
      .reader(holderReader())
      .processor(holderProcessor())
      .writer(holderWriter())
      .taskExecutor(taskExecutor()) // paralelo
      .build();
  }

  @Bean
  public TaskExecutor taskExecutor() {
    var exec = new ThreadPoolTaskExecutor();
    exec.setCorePoolSize(4);
    return exec;
  }
}

Riesgos y Mitigaciones

Principales riesgos técnicos identificados durante el análisis del código

Riesgo Impacto Mitigación
Axis 1.4 SOAP: WSDL de BCB/EDV no disponible o deprecado Alto Obtener WSDLs antes de Fase 5; mockear con WireMock en tests
iModel: entidades con lógica de negocio embebida en métodos Alto Auditar cada entidad antes de migrar; extraer lógica a @Service
Transacciones distribuidas EJB (TX propagation entre Facades) Alto Mapear explícitamente @Transactional(propagation=X) en todos los @Service
331 páginas XHTML: priorización incorrecta del desarrollo React Medio Mapear cada XHTML a ruta React antes de comenzar Fase 4
CrudDaoServiceBean: métodos auxiliares propios no en JpaRepository Medio Implementar como default methods en interfaces custom extendidas
JWT custom (UserInfo EJB @SessionScoped) → Spring Security principal Medio Migrar UserInfo a UserDetails de Spring Security desde Fase 2
JasperReports 6.11 → 6.21: cambios menores en API de exportación Bajo Test de regresión de reportes críticos (UIF, SMV) en staging
